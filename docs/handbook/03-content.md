# 03. Контент

## Откуда словарь

- **Только из файлов в репозитории.** Словарь — это TypeScript-массивы в `src/data/`, они собираются прямо в JS-бандл. Базы данных, CMS, внешних API и загрузки по сети нет.
- **Внешних источников в рантайме нет.** Транскрипции и примеры написаны вручную. Шапка `b1-01.ts` говорит, что МФА «в британском варианте (как заглавная форма в Cambridge/Oxford)», но сверки со словарями в репозитории нет: ни скрипта, ни ссылок. Как именно составлялся словарь, **не проверено**, в истории есть только первый коммит, где он появился целиком (3775165).
- **Аудио и картинок нет.** Произношение даёт синтез речи устройства в момент показа ([06](06-mini-app-screens.md#озвучка)), медиафайлов в словаре нет.
- **Тем в смысле поля `topic` нет.** Тематическая группировка сделана через `sets` (наборы).

## Формат записи

```ts
type Word = {
  id: string;            // en в нижнем регистре, пробелы → дефисы: "figure-out"
  en: string;            // заглавная форма: "figure out"
  ru: string[];          // 1–3 значения, от основного к оттенку; ru[0] — то, что спрашивается
  ipa: string;           // МФА в слэшах, британский неротический вариант
  pos: Pos;              // 'noun' | 'verb' | 'adj' | 'adv' | 'phrase' | 'phrasal'
  level: Level;          // 'A1' | 'A2' | 'B1' | 'B2' | 'C1' (в словаре только B1, B2)
  sets: string[];        // 'it-work' | 'meetings' | 'phrasal'; может быть пусто
  exampleEn: string;     // до 12 слов, «живой, не учебный»
  exampleRu: string;     // перевод примера
  collocations: string[];// сочетаемость, в словаре 2–3 шт.
  synonyms?: string[];   // «Близкие» на карточке
  falseFriend?: string;  // текст предупреждения, только у ложных друзей
  falseFriendRu?: string;// ложное значение одной строкой; всегда в паре с falseFriend
};
```

Пример обычной записи (`src/data/b1-01.ts`):

```ts
{
  id: 'achieve',
  en: 'achieve',
  ru: ['достигать', 'добиваться'],
  ipa: '/əˈtʃiːv/',
  pos: 'verb',
  level: 'B1',
  sets: ['it-work'],
  exampleEn: 'She achieved more in a year than most people do.',
  exampleRu: 'Она добилась за год больше, чем большинство людей.',
  collocations: ['achieve a goal', 'achieve results'],
  synonyms: ['accomplish', 'reach'],
},
```

Пример ложного друга:

```ts
{
  id: 'magazine',
  en: 'magazine',
  ru: ['журнал'],
  ipa: '/ˌmæɡəˈziːn/',
  pos: 'noun',
  level: 'B1',
  sets: [],
  exampleEn: 'She reads that magazine on the train every morning.',
  exampleRu: 'Она читает этот журнал в электричке каждое утро.',
  collocations: ['a fashion magazine', 'a magazine article'],
  falseFriend: 'Не «магазин». Магазин — это shop или store, а magazine — журнал.',
  falseFriendRu: 'магазин',
},
```

Как поля используются в интерфейсе:

| Поле | Где видно |
|---|---|
| `en` | Урок (крупно), карточка слова, разбор ошибок, «Мои слова»; озвучивается |
| `ipa` | Урок, карточка, разбор ошибок, «Мои слова». Если пусто (свои слова), строка не рисуется |
| `ru[0]` | Верный вариант ответа и дистрактор для других слов |
| `ru` целиком | Карточка («значение, значение»), разбор ошибок, «Мои слова»; поиск |
| `pos` | Чип `POS_LABEL` в уроке и на карточке, подпись «· сущ.» в списках; подбор дистракторов |
| `level` | Чип в уроке и на карточке; пул; ключ прогресса |
| `sets` | Тематические наборы; `custom` — чип «своё» |
| `exampleEn` | Карточка, слово подсвечено функцией `highlight` (для слов длиннее 4 букв ищется основа без двух последних букв, `achieve → achieved`) |
| `exampleRu` | Карточка, серым под примером |
| `collocations` | Карточка, серые «пилюли» |
| `synonyms` | Карточка, «Близкие: a · b» |
| `falseFriend` | Карточка, отдельный блок с тёплой рамкой и значком предупреждения |
| `falseFriendRu` | Обязательный вариант ответа |

## Правила словаря и проверка `check:words`

[`scripts/check-words.mjs`](../../scripts/check-words.mjs) собирает `src/data/words.ts` через esbuild в `.cache/words.mjs` и проверяет каждую запись. **Ошибки** (выводятся под заголовком `ПРОБЛЕМЫ:`; роняет ли это CI — см. оговорку ниже):

| Правило | Текст ошибки |
|---|---|
| `id` = `en.toLowerCase()` с пробелами → `-` | `id ≠ en: <id> / <en>` |
| Уникальный `id` | `дубль id: <id>` |
| `ipa` в слэшах | `ipa не в слэшах: <id>` |
| У многосложного слова есть `ˈ` (дифтонги считаются одним слогом) | `нет главного ударения: <id> <ipa>` |
| Нет `r` на конце слова (британский неротический; связующий `r` перед гласной можно) | `американский r на конце слова: <id> <ipa>` |
| Нет символов `ɝ ɚ ɹ` | `американский символ в МФА: <id> <ipa>` |
| `pos` из `POS_LABEL` | `неизвестная часть речи: <id>` |
| В `ru` 1–3 значения | `ru не 1–3 значения: <id>` |
| Пример не длиннее 12 слов | `пример длиннее 12 слов (<n>): <id>` |
| Есть `exampleRu` | `нет перевода примера: <id>` |
| Есть `collocations` | `нет сочетаемости: <id>` |
| `falseFriend` не длиннее 160 символов | `ложный друг длиннее 160 символов: <id>` |
| `falseFriend` и `falseFriendRu` идут парой | `falseFriend и falseFriendRu должны идти парой: <id>` |

**Предупреждение** (не ошибка): первые 4 буквы слова не найдены в примере — `слово не в начальной форме в примере`. Сейчас их три, и они нормальны: `come up with` / came, `find out` / found, `run out of` / ran.

Оговорка: скрипт печатает `ПРОБЛЕМЫ`, но **не завершается с ненулевым кодом** (`process.exit` в нём нет). Значит, `npm run check` и CI не упадут на ошибке словаря, её видно только в логе. Проверено чтением [`scripts/check-words.mjs`](../../scripts/check-words.mjs). Записано в [16](16-issues-backlog.md).

Скрипт также выводит статистику: счёт по уровню и части речи (с пометкой «← меньше 4, не хватит на дистракторы», если слов меньше 4), список ложных друзей, размеры наборов, число слов с синонимами, длину самого длинного примера.

## Как добавить или исправить слово

### Исправить перевод, пример, транскрипцию

1. Найти слово: `grep -rn "id: '<слово>'" src/data/`.
2. Поправить поле. Если меняется `ru[0]`, помнить, что это и верный ответ, и дистрактор для других слов той же части речи и уровня. Не делать `ru[0]` совпадающим с `ru[0]` другого слова того же уровня без нужды (см. C-01 ниже).
3. `npm run check:words`, затем `npm run check` (движок проверяет, что ни одна карточка не предлагает значение слова как ошибку).
4. PR в `main` → после мержа деплой сам ([13](13-development.md#деплой-и-откат)).

Прогресс пользователей при правке перевода, примера или МФА не страдает: он привязан к `id`.

### Добавить слово в существующий уровень

1. Дописать запись в подходящий файл `src/data/b1-0N.ts` или `b2-0N.ts` в блок нужной части речи. Порции по 40 — соглашение, а не требование кода.
2. Заполнить все обязательные поля. `id` — по правилу выше, уникальный.
3. Если это ложный друг — оба поля `falseFriend` и `falseFriendRu`.
4. Проверки, PR.

### Добавить новую порцию или уровень

1. Создать `src/data/<уровень>-<NN>.ts` с `export const WORDS_<...>: Word[] = [...]`.
2. Импортировать и добавить в массив `WORDS` в `src/data/words.ts`.
3. Для нового уровня (например, A2) больше ничего не нужно: уровень сам появится в переключателе на главной (`App.levels`), ключ прогресса `progress_a2` предусмотрен (`progress.ts` знает все `LEVELS`). Нужно минимум 4 слова каждой части речи уровня, иначе дистракторы будут браться с других уровней (`check:words` подскажет).
4. Проверить, что `check:engine` проходит: он прогоняет урок и варианты для всех слов.

### Добавить тематический набор

1. В `SETS` (`src/data/words.ts`) добавить `{ id, title, subtitle }`. `id` — латиница, он хранится в `settings.set`.
2. Проставить этот `id` в `sets` нужным словам.
3. Набор сам появится на главной (кнопки строятся из `SETS`). Размер набора выводит `check:words`, но только для трёх зашитых в скрипт наборов (`['it-work','meetings','phrasal']`), новый id надо дописать туда.
4. В `check:engine` есть проверка «тематические наборы по уровню» по зашитому списку наборов. Её стоит расширить.

### Удалить или переименовать слово

- **Удаление** словарного слова: его записи прогресса останутся в `progress_<уровень>` у пользователей, но ни на что не повлияют (в пул не попадают). При следующей записи уровня они сохранятся: слияние не удаляет незнакомые `id`. Это безвредный мусор.
- **Смена `id`**: для пользователей это новое слово, старый прогресс «осиротеет». Без нужды не менять.

## Свои слова

Да, пользователь может добавлять свои слова: «Мои слова» → «Добавить слово» ([06](06-mini-app-screens.md#своё-слово), [`src/lib/customWords.ts`](../../src/lib/customWords.ts)).

| Поле формы | Обязательное | Лимит | Во что превращается |
|---|---|---|---|
| Слово | да | 60 символов (`LIMITS.en`) | `en` (обрезка пробелов) |
| Перевод | да | 120 символов (`LIMITS.ru`) | Делится по запятым, пустые выбрасываются, берутся первые 3 → `ru` |
| Часть речи | да (по умолчанию «сущ.») | — | `pos`. Порядок кнопок: сущ., глаг., прил., нареч., фраз. глагол, выражение |
| Пример | нет | 200 (`LIMITS.example`) | `exampleEn` |
| Перевод примера | нет («Необязательно») | 200 | `exampleRu` |
| Уровень | не спрашивается | — | Текущий действующий уровень с главной |

Кроме полей формы: `ipa: ''`, `sets: ['custom']`, `collocations: []`.

**`id` своего слова** (`slugify`, `draftToWord`):
- `en` → нижний регистр → NFKD без диакритики (`naïve` → `naive`) → всё, кроме `[a-z0-9]`, заменяется на `-` → дефисы по краям убираются → первые 56 символов (`MAX_ID − 8`).
- Если латиницы нет (например, слово кириллицей), `id = w-<Date.now() в base36>`.
- Если `id` уже занят (словарём или своим словом), добавляется `-2`, `-3`… Значит, своё `achieve` получит `achieve-2` и будет отдельным словом.

Своё слово участвует в уроках **своего уровня** наравне со словарными, но только в наборе «По уровню». Дистракторы для него подбираются той же части речи. Своё «выражение» (`phrase`) получает дистракторы из любых частей речи, потому что словарных выражений нет.

Хранится каждое слово в отдельном ключе CloudStorage `cw_<id>` в JSON ([08](08-storage-contract.md#cw_id--своё-слово)). Удаление — из раскрытой карточки в «Моих словах», с подтверждением, вместе с прогрессом слова.

Редактировать своё слово **нельзя**: можно только удалить и добавить заново (прогресс при этом теряется).
