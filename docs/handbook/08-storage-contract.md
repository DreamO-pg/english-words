# 08. Контракт хранения

> В исходном плане здесь был «API бэкенда». **Бэкенда и эндпоинтов нет**: в `src` нет ни одного `fetch`/`XMLHttpRequest`, `initData` не используется. Единственный «внешний интерфейс» приложения — key-value хранилище **Telegram CloudStorage**. Поэтому раздел описывает каждый ключ как контракт: кто читает и пишет, формат, ограничения, ошибки, пример.
> Если в будущем появится сервер, проверка `initData` по HMAC обязательна с первого эндпоинта (AUDIT.md, 2.1).

## Транспорт

| Аспект | В Telegram | В браузере (фолбэк) |
|---|---|---|
| Хранилище | `Telegram.WebApp.CloudStorage` | `window.localStorage` |
| Имя ключа | как есть: `stats` | с префиксом: `ew:stats` |
| Авторизация | Telegram сам привязывает хранилище к паре «бот + пользователь». Приложение пользователя не знает и ничего не передаёт | Нет: хранилище браузера на origin `dreamo-pg.github.io` (или `localhost`) |
| Видимость | Только Mini App этого бота у этого пользователя, на всех его устройствах | Только этот браузер / WebView |
| Доступ с сервера | Нет: Bot API не даёт читать CloudStorage | — |

Лимиты CloudStorage (они же проверяются в `webapp.ts` до отправки):

| Лимит | Значение | Константа |
|---|---|---|
| Ключей на пользователя | до 1024 | (не проверяется кодом) |
| Длина ключа | 1–128 символов | `MAX_KEY = 128` |
| Символы ключа | `A-Z a-z 0-9 _ -` | `KEY_RE = /^[A-Za-z0-9_-]{1,128}$/` |
| Длина значения | до 4096 символов | `MAX_VALUE = 4096` |

## Обёртка `storage` — «клиент API»

[`src/telegram/webapp.ts`](../../src/telegram/webapp.ts), объект `storage`.

| Метод | Вызов CloudStorage | Возвращает | Бросает `StorageError`, если |
|---|---|---|---|
| `get(key)` | `getItem` | `string \| null` (пустая строка → `null`) | ошибка, таймаут |
| `getMany(keys)` | `getItems` | `Record<string, string>` без пустых | ошибка, таймаут, ответ `null` |
| `set(key, value)` | `setItem` | `void` | недопустимый ключ, значение > 4096, ошибка, таймаут, `ok = false` |
| `remove(key)` | `removeItem` | `void` | недопустимый ключ, ошибка, таймаут, `ok = false` |
| `keys()` | `getKeys` | `string[]` | ошибка, таймаут, ответ `null` |

Политика повторов: до 3 попыток, паузы 300 и 600 мс, таймаут каждой попытки 8000 мс.

## Сводная таблица ключей

| Ключ | Формат | Пишет | Читает | Когда пишется |
|---|---|---|---|---|
| `settings` | JSON `Settings` | `saveSettings` через очередь | `loadSettings` | Смена набора, уровня, размера; крестик плашки |
| `stats` | JSON `Stats` | `saveStats` через очередь | `loadStats` | Конец урока |
| `progress_<уровень>` | строка записей `id:box:errors:lastDay;…` | `saveLevelProgress` через очередь | `loadProgress`, `saveLevelProgress` | Конец урока; удаление своего слова |
| `progress_<уровень>_<N>` | то же, продолжение | то же | то же | При переполнении 4096 |
| `cw_<id>` | JSON `Word` | `saveCustomWord` напрямую | `loadCustomWords` | Сохранение своего слова |
| (localStorage) `ew-sync:pending` | JSON очереди | `sync.ts` | `sync.ts` при старте | Каждое `enqueue` и после записи |

Других ключей приложение не создаёт. Ключи, которые оно не узнаёт, игнорируются при чтении и не удаляются.

## `settings` — настройки

```ts
type Settings = {
  set: string;                 // 'level' | 'it-work' | 'meetings' | 'phrasal'
  level: Level;                // 'A1' | 'A2' | 'B1' | 'B2' | 'C1'
  lessonSize: 10 | 20 | 30;
  homeScreenHidden?: boolean;  // плашку «На домашний экран» закрыли крестиком
};
```

Пример значения:

```json
{"set":"it-work","level":"B2","lessonSize":20,"homeScreenHidden":true}
```

- Нет ключа → `DEFAULT_SETTINGS` = `{"set":"level","level":"B1","lessonSize":20}`.
- Битый JSON → тоже значения по умолчанию.
- Неполный объект дополняется значениями по умолчанию (`{...DEFAULT_SETTINGS, ...parsed}`).
- Значения не валидируются: неизвестный `set` даст пустой пул, неизвестный `level` — откат на первый уровень со словами (на экране, не в хранилище).
- Запись целиком, побеждает последняя.

## `stats` — статистика

```ts
type Stats = {
  lessons: number;      // законченных уроков всего
  answers: number;      // всех ответов (с повторными показами)
  correct: number;      // верных ответов из них
  streak: number;       // серия дней на момент последнего урока
  bestStreak: number;
  lastDay: number;      // день последнего урока (от 2020-01-01)
  history: { d: number; n: number; ok: number }[]; // последние 20 уроков: день, слов, с первого раза
};
```

Пример (вымышленный пользователь, три урока за два дня):

```json
{"lessons":3,"answers":71,"correct":60,"streak":2,"bestStreak":2,"lastDay":2507,
 "history":[{"d":2506,"n":20,"ok":15},{"d":2507,"n":20,"ok":17},{"d":2507,"n":3,"ok":3}]}
```

- Нет ключа или битый JSON → `EMPTY_STATS` (все нули, пустая история).
- Неполный объект дополняется нулями.
- Размер ограничен историей в 20 записей; `check:engine` проверяет, что значение остаётся короче 4096 символов.
- Запись целиком, побеждает последняя.

## `progress_<level>` — прогресс уровня

**Имя:** `progress_` + уровень в нижнем регистре: `progress_b1`, `progress_b2` (предусмотрены и `progress_a1`, `progress_a2`, `progress_c1`).

**Шарды:** если значение не помещается в 4096 символов, продолжение лежит в `progress_b1_1`, `progress_b1_2` и т. д. Номер шарда — после второго `_`. Порядок шардов при чтении не важен: все записи уровня объединяются.

**Формат значения:** записи через `;`, поля записи через `:`:

```text
<id слова>:<box 1–5>:<errors 0–99>:<lastDay>
```

Пример (вымышленный):

```text
achieve:4:0:2490;afford:1:2:2507;avoid:2:0:2505;figure-out:5:1:2470
```

| Поле | Тип | При чтении (`parseLevelProgress`) | При записи (`serializeLevelProgress`) |
|---|---|---|---|
| `id` | строка `[a-z0-9-]` | непустая | как есть |
| `box` | целое | округляется и зажимается в 1–5 | как есть |
| `errors` | целое | `max(0, round(x))` | `min(99, errors)` |
| `lastDay` | целое | `round(x)` | как есть |

- Запись не из 4 полей или с нечисловым полем выбрасывается целиком («лучше потерять одно слово, чем сделать вид, что его показывали в нулевой день»). Пустые куски (`;;`) пропускаются.
- Вместимость: при `id` средней длины ≈ 200–250 записей на ключ. Сейчас уровни по 200 и 240 слов, то есть при полном прохождении уровня B2 будет 2 шарда.
- Чтение: `getKeys` → ключи, у которых после `progress_` идёт известный уровень → `getItems`. Два обращения вместо одного на ключ.
- Запись: всегда через `saveLevelProgress`, который сначала читает облако и сливается ([07](07-mini-app-tech.md#запись-очередь-syncts)). Лишние хвостовые шарды удаляются только после записи новых.

## `cw_<id>` — своё слово

**Имя:** `cw_` + `id` своего слова (`[a-z0-9-]`, до 56 символов от `slugify`, плюс возможный суффикс `-2`…; `parseCustomWord` принимает до 64).

**Значение:** JSON полного `Word`:

```json
{"id":"gizmo","en":"gizmo","ru":["штуковина","приспособление"],"ipa":"","pos":"noun","level":"B1",
 "sets":["custom"],"exampleEn":"What does this little gizmo do?","exampleRu":"Что делает эта штуковина?","collocations":[]}
```

Валидация при чтении (`parseCustomWord`), невалидная запись пропускается:
- JSON-объект;
- `id` — строка `/^[a-z0-9-]{1,64}$/`;
- `en` — непустая строка;
- `ru` — непустой массив строк (берутся первые 3);
- `pos` — ключ `POS_LABEL`;
- `level` — один из `LEVELS`;
- `exampleEn`, `exampleRu` — строки, иначе `''`;
- `ipa`, `sets`, `collocations` при чтении **перезаписываются** на `''`, `['custom']`, `[]`.

Ограничения записи: поля формы обрезаются (60 / 120 / 200 символов), поэтому значение заведомо меньше 4096; на всякий случай `saveCustomWord` проверяет длину и бросает `Error('слово слишком длинное')`.

Ошибки: сбой `set` — в форме «Не удалось сохранить слово…»; сбой `remove` — плашка «Не удалось удалить слово…».

## `ew-sync:pending` — очередь на устройстве

Ключ **`localStorage`** (не CloudStorage), не имеет префикса `ew:`, чтобы не попасть в `storage.keys()` браузерного фолбэка.

```ts
type Pending = {
  levels: Partial<Record<Level, { progress: LevelProgress; removed: string[]; seq: number }>>;
  stats?: { value: Stats; seq: number };
  settings?: { value: Settings; seq: number };
};
```

Пример:

```json
{"levels":{"B1":{"progress":{"achieve":{"box":2,"errors":0,"lastDay":2507}},"removed":[],"seq":7}},
 "stats":{"value":{"lessons":1,"answers":22,"correct":20,"streak":1,"bestStreak":1,"lastDay":2507,"history":[{"d":2507,"n":20,"ok":18}]},"seq":8}}
```

- Пустая очередь — ключ удаляется.
- Битый JSON — очередь считается пустой.
- `progress` в очереди — **весь уровень**, каким он был в памяти, а не только изменённые слова.

## Коды ошибок

Своих кодов нет. Все сбои хранилища — `StorageError` с текстом ([05](05-ui-texts.md#тексты-не-для-пользователя)). Как они видны пользователю:

| Где сбой | Что видит пользователь |
|---|---|
| Чтение при запуске | Экран «Не удалось загрузить прогресс» |
| Запись очереди | Плашка «Не всё сохранено в облако…» + авто-повтор каждые 20 с |
| Сохранение своего слова | Красный текст в форме |
| Удаление своего слова | Плашка «Не удалось удалить слово…» |
