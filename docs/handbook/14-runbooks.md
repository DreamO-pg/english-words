# 14. Инструкции на типовые случаи

Перед любым случаем помнить: **сервера нет**. Всё, что можно сломать, — это сайт на GitHub Pages, настройка кнопки в BotFather, клиент пользователя или CloudStorage Telegram.

## Бот не отвечает

**Это нормально.** У бота нет кода, он не отвечает ни на `/start`, ни на сообщения ([04](04-bot-in-telegram.md)).

Что ответить пользователю: «Бот работает через кнопку меню „Слова“ слева от поля ввода. Нажмите её, откроется тренажёр».

Если кнопки меню нет:
1. @BotFather → `/mybots` → бот → Bot Settings → Menu Button. Должен стоять тип «Web App» с URL `https://dreamo-pg.github.io/english-words/` и подписью «Слова».
2. Если стоит «Commands» или пусто — настроить заново ([12](12-configuration.md#botfather)).
3. Клиент Telegram может кэшировать меню. Пусть пользователь перезайдёт в чат или перезапустит Telegram.

## Mini App не открывается

Идти по шагам сверху вниз.

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| Ошибка WebView, «страница не найдена», 404 | Pages выключен, репозиторий переименован или неверный URL в BotFather | Открыть URL в браузере. Проверить Settings → Pages (Source: GitHub Actions) и `gh api repos/DreamO-pg/english-words/pages`. Сверить URL в BotFather, включая слэш на конце |
| Белый экран | Ошибка в JS или не загрузился бандл | Открыть URL в браузере и посмотреть консоль. Если там ошибка — откатить последний коммит ([13](13-development.md#откат)). Проверить, что `base` в `vite.config.ts` совпадает с путём сайта |
| Белый экран только после деплоя, в браузере всё хорошо | Кэш WebView держит старый `index.html` со ссылками на удалённые файлы | Подождать несколько минут, закрыть и снова открыть Mini App; на Desktop — перезапустить клиент |
| «Не удалось подключиться к Telegram» | `telegram.org` недоступен у пользователя (сеть, блокировка) | «Повторить». Если повторяется — проблема сети пользователя (VPN, прокси) |
| «Обновите Telegram» | Клиент поддерживает Mini Apps ниже 6.9 | Обновить Telegram |
| «Загружаю прогресс…» висит долго, потом «Не удалось загрузить прогресс» | Нет связи с серверами Telegram, CloudStorage не отвечает (3 попытки по 8 с) | «Повторить». Прогресс не потерян, он в облаке |
| «Что-то сломалось» | Исключение при рендере | «Перезапустить». Если повторяется у пользователя — нужна консоль WebView ([13](13-development.md#запуск-внутри-telegram-с-тестовым-ботом)) или воспроизведение на тестовом боте; частая причина в прошлом — битые данные, сейчас они отфильтровываются |
| Деплой не выкатился | Упал `npm run check` или сборка | Actions → последний запуск → лог. Исправить, запушить |
| Всё открывается, но нет звука | На устройстве нет `speechSynthesis` или английского голоса | Не ошибка приложения. Кнопок звука в этом случае нет |

Проверка состояния GitHub Pages: [githubstatus.com](https://www.githubstatus.com/).

## Плашка «Не всё сохранено в облако…» не уходит

1. Нажать «Повторить» на плашке.
2. Приложение само повторяет каждые 20 с и при возврате в окно.
3. Данные лежат на устройстве (`ew-sync:pending`) и отправятся при следующем запуске **на этом же устройстве**. Удалять Telegram или чистить кэш WebView до этого не стоит: несохранённое пропадёт.
4. Если не уходит долго при нормальной сети — возможна ошибка лимита: значение длиннее 4096 символов или больше 1024 ключей. Проверка длины есть до отправки, переполнение 1024 ключей кодом не проверяется (только при очень большом числе своих слов). Воспроизвести на тестовом боте.

## Исправить перевод (или пример, транскрипцию)

1. Найти слово: `grep -rn "id: 'benefit'" src/data/`.
2. Поправить поле в `src/data/b*-*.ts`. Правила — [03](03-content.md#как-добавить-или-исправить-слово).
3. Прогнать проверки:

```bash
npm run check:words
```

```bash
npm run check
```

Прочитать вывод `check:words` глазами: строки после `ПРОБЛЕМЫ:` CI не остановят.
4. Ветка → PR → мерж. Деплой автоматический. Прогресс пользователей не затрагивается (он по `id`).

Если меняется `ru[0]`: это и правильный ответ, и вариант-ошибка для других слов той же части речи и уровня. Проверить, что новый `ru[0]` не совпадает с `ru[0]` другого слова уровня без нужды.

## Добавить набор слов

**Тематический набор** (например, «Путешествия»):
1. `src/data/words.ts`, массив `SETS`: `{ id: 'travel', title: 'Путешествия', subtitle: 'Аэропорт, отель, дорога' }`.
2. Проставить `'travel'` в `sets` нужным словам (или добавить новые слова).
3. Желательно не меньше ~10 слов на каждом уровне и по 4+ слова каждой части речи, иначе дистракторы возьмутся из всего уровня.
4. В `scripts/check-words.mjs` и `scripts/check-engine.mjs` наборы перечислены списком `['it-work','meetings','phrasal']` — дописать новый.
5. Проверки, PR.

**Новый уровень или порция слов** — [03](03-content.md#добавить-новую-порцию-или-уровень).

## Сбросить прогресс пользователя по его просьбе

**Готового способа нет.** Прогресс лежит в CloudStorage пользователя у этого бота. Сопровождающий его **не видит и не может изменить**: Bot API не даёт доступа к CloudStorage, сервера нет, и в интерфейсе нет кнопки «Сбросить прогресс».

Что можно ответить и сделать:

| Просьба | Вариант |
|---|---|
| «Хочу начать заново» | Пока нет кнопки, честно сказать, что сброс не поддерживается. Добавить функцию «Сбросить прогресс» — в бэклоге ([16](16-issues-backlog.md)) |
| «Хочу учить другой уровень или набор с нуля» | Выбрать другой набор или уровень: прогресс считается по пулу, у нового набора свой счётчик «знаю». Сами слова при этом общие: прогресс слова один на все наборы |
| «Удалите мои данные» | Данных на стороне проекта нет. Всё, что есть, — в CloudStorage Telegram у этого бота. Удалит ли его удаление чата с ботом или блокировка бота, **не проверено** (Telegram это не документирует). Надёжный путь — встроенная функция сброса (бэклог) |

Если сброс нужен срочно, минимальная реализация такая: на экране «Мои слова» кнопка с подтверждением, которая вызывает `storage.keys()` и `storage.remove()` для всех `progress_*`, `stats` (и по желанию `settings`, `cw_*`), очищает `ew-sync:pending` и состояние в памяти. Удалять через `storage.remove` по одному: `removeItems` в обёртке не реализован.

## Сменить токен бота

Токен **нигде не используется** ни в коде, ни в CI. Поэтому:
1. @BotFather → `/mybots` → бот → API Token → **Revoke current token**.
2. Больше ничего делать не нужно: Menu Button, Mini App и CloudStorage привязаны к боту, а не к токену. Пользователи ничего не заметят.

Когда понадобится: если токен утёк (например, его вставили в чат или код). Если когда-нибудь появится сервер, токен будет храниться в его окружении, и после смены его нужно будет обновить там.

## Восстановить из бэкапа

- **Код и словарь**: из git. Нужную версию файла — `git checkout <коммит> -- <путь>`, всё состояние — `git revert` / новый коммит. Сайт пересоберётся при push в `main`.
- **Сайт**: пересобрать — Actions → Deploy to GitHub Pages → Run workflow.
- **Данные пользователей: восстановить нельзя.** Бэкапов CloudStorage нет и снаружи их не сделать. Если версия приложения испортила данные (например, записала пустой прогресс), остаётся только:
  1. немедленно откатить версию, чтобы порча не продолжалась;
  2. если у пользователя на устройстве есть неотправленная очередь `ew-sync:pending`, она при следующем запуске сольётся с облаком по `lastDay` и частично вернёт данные — значит, после отката пользователю стоит открыть приложение на том устройстве, где он занимался последним.
  
  Именно поэтому чтение и запись устроены так осторожно ([07](07-mini-app-tech.md#хранение-и-синхронизация)): ошибка чтения не превращается в пустой прогресс, перед записью облако перечитывается и сливается.

## Перенести на другой сервер или домен

Перенос **хостинга** (другой GitHub-аккаунт, свой домен, Netlify, Cloudflare Pages, свой nginx):
1. Если путь сайта меняется (не `/english-words/`), поменять `base` в `vite.config.ts` (например, `'/'` для корня домена).
2. Собрать `npm run build`, выложить `dist/` на новый хостинг с HTTPS. Для GitHub Pages со своим доменом — Settings → Pages → Custom domain (и файл `CNAME` в `public/`).
3. В @BotFather поменять URL Menu Button на новый (со слэшем на конце, если сайт в подкаталоге).
4. Проверить в Telegram: кнопка открывает приложение, прогресс на месте.

Что будет с данными:
- **Прогресс в CloudStorage сохранится**: он привязан к боту, а не к домену.
- **Неотправленная очередь** `ew-sync:pending` лежит в `localStorage` старого домена и на новый **не переедет**. Перед переездом стоит убедиться, что плашки «Не всё сохранено» ни у кого нет (на практике это не проверить, поэтому лучше переезжать в спокойное время и, если можно, держать старый адрес рабочим несколько дней).
- **Пользователи в обычном браузере** (не в Telegram) потеряют прогресс: он в `localStorage` старого домена.

Перенос на **другого бота**: прогресс пользователей **не переносится**. CloudStorage у каждого бота своё, перенести его можно только из самого Mini App (старый бот читает, новый пишет), а такого кода нет. Без крайней необходимости бота не менять.

## Новая версия Bot API

После выхода новой версии Bot API или Mini Apps:
1. Прочитать changelog: не стало ли обязательным что-то, что приложение не делает, не изменилось ли поведение используемых методов ([07](07-mini-app-tech.md#telegram-webapp-api)).
2. SDK подключён без версии, поэтому новое поведение приходит само. Открыть приложение на свежем клиенте и пройти урок.
3. Отдельно — открытая проверка T-04: ограничение Bot API 10.2 (методы Mini App работают только с исходного домена) при URL без слэша и редиректе 301.
