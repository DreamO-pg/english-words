# 13. Разработка

## Что нужно

- Node.js ≥ 20 (`engines`), в CI используется 22. На Node 20 скрипты `check:*` работают, это проверено на v20.10.0.
- npm (lock-файл v3).
- Для проверки внутри Telegram — тестовый бот и HTTPS-адрес (см. ниже).

## Локальный запуск в браузере

```bash
npm install
```

```bash
npm run dev
```

Приложение откроется по адресу `http://localhost:5173/english-words/`, путь совпадает с GitHub Pages из-за `base`.

В браузере приложение работает целиком:
- `telegram-web-app.js` грузится, но отдаёт `platform: 'unknown'`, и обёртка уходит в фолбэк;
- данные хранятся в `localStorage` с префиксом `ew:` (очистить — DevTools → Application → Local Storage);
- «назад» работает по **Escape**;
- haptic молчит, подтверждения через `window.confirm`;
- плашки «На домашний экран» нет.

Проверить собранную версию так, как её отдаст Pages:

```bash
npm run build
```

```bash
npm run preview
```

Сборка будет доступна по адресу `http://localhost:4173/english-words/`.

### Полезные приёмы отладки в браузере

| Что воспроизвести | Как |
|---|---|
| Ошибку загрузки | Чтение должно падать **до старта** приложения, поэтому подмена из консоли после загрузки не поможет. Варианты: запретить сайту хранилище в настройках браузера или через DevTools Protocol выполнить `Storage.prototype.getItem = () => { throw new Error() }` до загрузки страницы (`Page.addScriptToEvaluateOnNewDocument`; так снимались скриншоты для [06](06-mini-app-screens.md)) |
| Сбой записи и плашку | Подменить `Storage.prototype.setItem`, чтобы он бросал для ключей `ew:*`, и пройти урок |
| Экран «Не удалось подключиться к Telegram» | Заблокировать `telegram.org` в DevTools (Network request blocking) и открыть адрес с `#tgWebAppData=x` |
| Поведение в Telegram конкретной версии | Подложить свой `window.Telegram.WebApp` до загрузки приложения при заблокированном `telegram.org` (пример мока: AUDIT.md, этап 4) |
| Просроченное слово | `localStorage.setItem('ew:progress_b1', 'magazine:1:1:2400')` и перезагрузить |

## Запуск внутри Telegram с тестовым ботом

Mini App в Telegram открывается только по **HTTPS**. Варианты:

1. **Свой GitHub Pages из форка** (самый простой и точный).
   - Форкнуть репозиторий (имя `english-words`, иначе поменять `base`).
   - Settings → Pages → Source → GitHub Actions; запушить ветку `main`.
   - Создать тестового бота в @BotFather (`/newbot`), Menu Button → `https://<ваш-логин>.github.io/english-words/`.
2. **Туннель на локальный сервер** (cloudflared, ngrok и т. п.).
   - `npm run dev` или `npm run preview`, туннель на порт 5173/4173, Menu Button тестового бота → `https://<туннель>/english-words/`.
   - Vite 5.4.12+ по умолчанию отклоняет запросы с чужим `Host`. Для туннеля локально (не коммитить!) нужно добавить хост в `server.allowedHosts` / `preview.allowedHosts` в `vite.config.ts`. **Не проверено** в этом проекте.
3. **Тестовое окружение Telegram** (test DC) — отдельный аккаунт и бот на тестовых серверах; там разрешён и HTTP. В проекте не использовалось.

Важно: у тестового бота **своё** CloudStorage, с боевым прогрессом оно не пересекается. Это удобно, данные боевых пользователей не затронуть.

Для отладки WebView: Telegram Desktop (Settings → Advanced → Experimental → Enable webview inspecting), Android (`chrome://inspect` при включённой отладке WebView в Telegram), iOS (Safari → Develop при включённой опции в Telegram). Пути в меню зависят от версии клиента, **не проверено**.

## Проверки

Тестового фреймворка (Jest, Vitest) нет. Вместо него три самописных скрипта на `node`, которые собирают нужные модули через esbuild в `.cache/` и проверяют их.

| Команда | Что проверяет | Проверок | Код выхода при провале |
|---|---|---|---|
| `npm run check:words` | Словарь: id, дубли, МФА (ударение, британский `r`), часть речи, 1–3 значения, длина примера, перевод примера, сочетаемость, пары ложного друга | правила по каждому слову | **0** (печатает `ПРОБЛЕМЫ`, но не падает) |
| `npm run check:engine` | Дистракторы, «верные ошибки», ложные друзья, Лейтнер и сроки, местный день, полный урок, пропорции, просроченные, наборы по уровню, свои слова, «повторить ошибки», шардирование, серия, сводка | 56 | 1 |
| `npm run check:storage` | Сбои чтения, лимиты CloudStorage, слияние, запись поверх другого устройства, шарды, очередь при сбое и после перезапуска, свои слова, мок `Telegram.WebApp.CloudStorage` | 37 | 1 |
| `npm run lint` | ESLint | — | ≠ 0 |
| `npm run check` | Всё выше по очереди | — | первый провал |
| `npm run build` | `tsc --noEmit` + сборка | — | ≠ 0 |

Перед PR: `npm run check && npm run build`. После правки словаря **читать вывод `check:words` глазами**: CI ошибки словаря не остановят.

Чего не хватает (из AUDIT.md, раздел 6, и по факту): тестов компонентов и сквозных сценариев в браузере, проверок на живом клиенте Telegram.

## Линтеры и форматирование

- ESLint 9, конфиг [`eslint.config.js`](../../eslint.config.js). Сейчас замечаний нет.
- Prettier не подключён. Стиль кода по факту: 2 пробела, одинарные кавычки, точки с запятой, висячие запятые, ширина около 100 символов.
- Комментарии в коде на русском, объясняют «почему».

## Ветки и PR

- Основная ветка `main`, защиты на ней нет.
- Принятый процесс (по истории): работа в ветке, PR в `main`, на PR автоматически запускается `check.yml`, затем мерж (merge commit). Пример — PR #1 `docs/audit`, смержен 2026-11-12.
- Сообщения коммитов на русском, в повелительном наклонении («Защитить прогресс…», «Исправить логику обучения…»), с подробным телом списком.
- **Правило документации:** если PR меняет поведение бота или Mini App, логику обучения, словарь, хранение, тексты или инфраструктуру, в том же PR обновляются `docs/handbook/` и соответствующие страницы Notion (записано в `CLAUDE.md`).

## Деплой и откат

### Деплой

Автоматически: любой push в `main` (в том числе мерж PR) → `deploy.yml` → `npm run check` → `npm run build` → GitHub Pages. Занимает около минуты. Вручную: Actions → Deploy to GitHub Pages → Run workflow (собирает текущий `main`).

Проверить после деплоя:
1. Actions → последний запуск зелёный.
2. Открыть `https://dreamo-pg.github.io/english-words/` в браузере — главная рисуется.
3. Открыть бота → кнопка меню → приложение открывается, прогресс на месте. Если видна старая версия, закрыть и открыть Mini App ещё раз (кэш WebView).

### Откат

Отдельного механизма нет, откат делается коммитом в `main`:

```bash
git revert <плохой-коммит>
```

```bash
git push origin main
```

`deploy.yml` выложит предыдущее состояние. Выбрать старый артефакт в Settings → Pages нельзя, а `workflow_dispatch` собирает только голову ветки, поэтому основной путь — revert.

**Совместимость данных при откате.** Пользовательские данные в CloudStorage не откатываются. Если плохая версия успела записать данные в новом формате, старая версия должна уметь их прочитать. Сейчас все читатели терпимы к лишним полям и битым записям ([10](10-data.md#миграции)), но при смене формата ключей это надо продумать заранее.
